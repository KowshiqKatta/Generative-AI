feat(rag): add inline citations, cross-encoder reranking, and live progress

Answers now cite their sources, and retrieval no longer hands the LLM a
noisy top-k.

Citations
- generate_answer_node builds a numbered context block and instructs the
  model to attach a bracketed marker to each claim; a Sources list with
  paper titles and page numbers is appended to the answer.
- Chunks are grouped by (title, page) or URL, so several chunks from one
  page collapse into one citation instead of four consecutive ones.
- prune_citations() drops sources the model never referenced and
  renumbers the rest from 1 in a single regex pass, so a swap (3->1,
  1->2) cannot double-map.

Reranking
- New backend/reranker.py wrapping FlashRank. retrieve_from_vectorstore
  overfetches 5x the requested k (capped at 40) and the cross-encoder
  trims back to k.
- Motivated by eval_results.json: Contextual Recall 1.00 alongside
  Contextual Relevancy 0.09-0.27 is the signature of a bi-encoder that
  retrieves the right passage and then buries it.
- Reranking is an optimisation, not a dependency: a missing model or a
  failed inference logs a warning and falls back to similarity order.
- rerank_score is attached to chunk metadata for the state inspector.

UI
- The graph run streams in combined updates+messages mode and reports
  each stage into an st.status panel. updates mode is required because
  the ToolNode makes no LLM call and is invisible to messages mode.
- The rendered answer is read back from graph state rather than the
  token stream, since the Sources block is appended after generation.
  This also fixes verify_claim, which never streamed at all.
- Graph-run exceptions are caught and surfaced in the status panel
  instead of crashing the page with a traceback.

Build
- Add flashrank. Drop chromadb and arxiv, both declared but unimported.
- Dockerfile pre-downloads the reranker model, adds a healthcheck, and
  stops copying main.py and sessions.json into the image.

Docs
